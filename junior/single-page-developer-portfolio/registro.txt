#Desafio: Frontend Mentor - single-page-developer-portfolio

Nível: Junior
Recursos e avaliação: implementação usando claude code no terminal do vscode. Comentário: Neste desafio foi usado o openspec com o intuito de testar o framework como um gestor de implementação de projeto a partir de uma especificação já definida, sendo após a implementação de fundação definida em uma especificação, inserir um novo recurso no desafio sem quebrar o que foi construído e manter um registro documentando. Assim o openspec é avalidado como uma ferramenta de uso para implementação que possui evoluções de versões. Foi utilizado playwright + Chromiume e axe-core para teste de interface e node test para teste de logica pura. 


Fluxo da implementação: openspec foi instalado e iniciado dentro da pasta do projeto; Os layout do figma foram convertidos para png e inseridos na pasta /design. Primeira ação necessária foi usar a skill explore aplicada no arquivo de especificacao.md, onde após uma discussão de decisão foi gerado o arquivo decisoes-do-projeto.md que reuniu todas as decisões e conteudos do arquivo especificacao.md de modo organizado. O arquivo decisoes-do-projeto.md foi utilizado para gerar as instrucoes do config.ymal e aplicado a skill porpose para a geração das changes, e criação do CLAUDE.md a partir do /init, logo após ele foi excluido, sendo a fonte da verdade do projeto as changes. Foram criadas três changes. change 1 para criar testes seguindo a metodologia TDD, a change 2 para implementação do layout e change 3 definir evolução...


Ocorrências: No momento de execução da change 1 o agente gastou muito tempo na implementação de testes, pois houve de incluir o teste playwright (end to end) sem o layout ter ficado completamente pronto, fato foi corrigido e foi transferido para a change 2 o teste. Ao final da change 2, foi verificado algumas diferenças no layout modelo e o que foi implementado, assim em um prompt foi pedido uma verificação usando playwright para comparar os layout, onde as questões foram detectadas e corrigidas, ficando como lição, o playwright funciona como uma ferramenta de revisão e correção sem o humano precisar indicar no layout as falhas, reduzindo a possibilidade de entrar em prompts de tentativa e erro para ajustar o layout, visto que esse tipo de correção constuma ser complexas pois envolve a indicação de elementos no layout.

PARA O PRÓXIMO DESAFIO: Ao escrever o arquivo de decisão gerado pelo explore pedir para definir no documento o que irá ser usado no config.yaml e no claude.md para que não haja duplicidade e sobreposição de instruções.
